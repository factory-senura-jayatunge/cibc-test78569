# Release note: PB-2210, loan-to-value early warning on secured credit lines

**Line of business:** Private Banking
**Files changed:** `src/lob/private-banking/credit.js`, `src/lob/private-banking/index.js`, `tests/pb-credit.test.js`, `tests/pb-statements.test.js`

## Summary

`creditSummary` now returns `ltvStatus`, classified by a new exported `ltvStatus(ratio)` function: `ok` below 0.60, `watch` from 0.60 to 0.70 inclusive, and `margin-call-warning` above 0.70. The Private Banking statement's "Credit facility" section shows a new `LTV status` row directly after `Loan-to-value`. The change stays inside `src/lob/private-banking/` and adds no imports, so regression stays inside Private Banking (plus the always-on smoke suite).

## Risks

- An empty collateral account makes `loanToValue` return `Infinity`, which maps to `margin-call-warning` even when nothing is drawn. This fails safe but can raise a false warning. Credit Risk should confirm. (Low, new.)
- The status is classified from the LTV after `roundRatio` (four decimals), so a true LTV of 0.70004 shows `watch`. Credit Risk should confirm this reading of "above 0.70". (Low, new.)
- The AC3 guard imports other lines of business' statement modules, but `regression/catalog.json` `covers` for `pb-statements` was not widened, so a later change to those modules will not select this guard. (Low, new.)
- Pre-existing and not changed: `src/platform/statements.js:20` writes the client name to audit detail, `src/server.js` has no authentication, and `credit.js` still imports `investors-edge/trading.js` (known debt).
